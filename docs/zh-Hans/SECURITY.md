# 安全

[English](../SECURITY.md) · [Deutsch](../de/SECURITY.md) · [Ελληνικά](../el/SECURITY.md) · [Español](../es/SECURITY.md) · [Français](../fr/SECURITY.md) · [Italiano](../it/SECURITY.md) · [日本語](../ja/SECURITY.md) · [한국어](../ko/SECURITY.md) · **简体中文**

终端流量和项目内容均由你的设备进行端到端加密，私钥绝不会以未加密的形式离开你的设备。后端负责路由连接并存储加密后的项目记录，但既不会执行命令，也无法看到这些内容的明文。有关完整的威胁模型、加密机制和已知限制，请参阅[加密设计](../CRYPTOGRAPHY.md)（英文）。该设计与实现目前尚未经过独立第三方审计。

## 共享所授予的权限

共享终端会授予接收方完全的控制权，使其在该电脑上拥有与你相同的操作系统权限。将终端共享到项目中后，该项目内你的所有好友（包括后续加入的好友）都可以访问它。由于共享终端以你的身份运行，其中的任何成员都可以以你的身份执行 `kodosi` 命令，并读写该电脑上的文件。因此，请只将终端共享给你完全放心托付这台电脑的人。

Kodosi 不会限制参与成员或其 Agent 在共享终端或项目中的操作。移除好友会立即撤销对方对你终端的访问权限，并使双方各自退出对方拥有的项目。屏蔽用户会产生同样效果，并阻止对方日后再向你发送好友请求。

任何让新的人进入你的终端或项目的更改，都会先在发起更改的设备上的 Kodosi 应用中征求你的同意，即使是 `kodosi` 命令（例如代表某个 Agent）发起的更改也是如此。这可以防止误操作和 Agent 的越权行为；但在你共享的终端中输入命令的人是以你的身份操作的，可以绕过这一确认。

你的每一台已批准设备都可以控制你的全部终端、选择与谁共享这些终端、在你其他运行 Kodosi 的电脑上启动新终端，以及向这些电脑上的 Dosi 发送消息（Dosi 在本机执行操作时拥有与你直接使用时相同的本地权限）。移除设备后，该设备对终端和 Dosi 的访问权限将随之撤销。

### 画布与共享浏览器

凡是有权访问某个终端的人，都可以查看和编辑其画布上的文件，并使用其共享浏览器。因此，在共享浏览器中请只登录所有参与成员都应有权使用的账号。共享终端绝不会复用你在私有终端中保存的浏览器登录状态。画布上的文件都是宿主机上的普通文件。

HTML 页面和实时文档视图运行在隔离的框架中，既没有网络访问权限和文件访问权限，也没有持久化存储。共享浏览器处于唤醒状态时，其调试端口以及各窗口的驱动端口会绑定到 `127.0.0.1` 或 `::1`，这意味着同一台电脑上的其他本地操作系统用户账号也能访问这些端口。共享浏览器中的网站在每次用户或 Agent 操作下最多只能向终端文件夹保存一个下载文件，且仅在你主动执行复制操作时才能访问剪贴板。

在 Linux 上，Kodosi 仅在 Chromium 沙盒能够正常运行的环境中渲染页面。在 Ubuntu 上，Kodosi 附带了 AppArmor 配置文件，允许应用、其渲染进程以及 Kodosi Browser 创建 Chromium 沙盒所需的用户命名空间。出于同样原因，共享浏览器在 Linux 上不会以 root 身份运行。

Kodosi 应用本身不内置 Kodosi Browser。在一台电脑上首次打开共享浏览器时，Kodosi 会从 Kodosi 在 GitHub 上的发布版本中下载它，并每日在 `updates.kodosi.com` 上的 Kodosi 更新源中检查更新。只有当更新源包含 Kodosi 更新密钥的有效签名，且下载文件的 SHA-256 校验值与更新源一致时，Kodosi 才会接受该下载。

### Kodosi Browser 会向 Google 发送什么

Kodosi Browser 是 Chromium，它会自行调用以下 Google 服务，且其中任何一项都不会携带你的 Cookie：

- 组件更新（例如已吊销证书列表）：大约每 5 小时向 `update.googleapis.com` 查询新版本，并从 Google 的下载服务器（例如 `edgedl.me.gvt1.com`）下载。它会发送每个组件的 ID 和版本、自身的版本以及操作系统和处理器信息，但不会发送任何浏览数据。
- 安全浏览：它会从 `safebrowsing.googleapis.com` 获取并保存危险网站列表，过程中只发送其列表的状态。当某个页面的地址与列表匹配时，它会发送该地址哈希值的前 4 个字节，绝不发送地址本身。如果它在你电脑上运行的钓鱼检测将某个页面判定为钓鱼页面，它会将该页面的地址发送到 `sb-ssl.google.com` 进行确认。
- 网络时间：当它不确定当前时间时，会向 `clients2.google.com` 查询；即使你的时钟不准，查询结果也能让它判断网站的证书是否已过期。该请求不包含任何关于你的信息。

**Google 表单预测** 会一直保持关闭，直到你在 **设置 › 浏览器** 中将其开启。开启后，Kodosi Browser 会针对其显示的每个表单，将由网站名称和表单各字段名称生成的哈希值发送到 `content-autofill.googleapis.com`，Google 则会答复每个字段的用途。当你提交表单时，它还会告知每个字段填写的是哪类数据，但绝不会告知你输入的内容。Kodosi Browser 绝不会在搜索之前预先连接 `www.google.com`，也绝不会携带你的 Google Cookie 向 Google 询问 Chrome 自带的地址栏能否提供 AI 模式。

**跨站 Cookie** 同样会一直保持关闭，直到你在 **设置 › 浏览器** 中将其开启。关闭期间，显示在另一网站页面中的网站（例如 YouTube 视频或登录按钮）无法在那里获取自己的 Cookie，因此无法在你访问的各个网站之间认出你。

### 电脑的屏幕

在电脑的 Kodosi 设置中打开屏幕共享后，你的每台已批准设备都可以在这台电脑终端的画布上查看并控制它的整个屏幕，而不只是终端。好友永远看不到它，即使在你与他们共享的终端中也是如此；画面、输入和剪贴板文本都与终端本身一样经过端到端加密传输。Kodosi 中一个独立的部分负责捕获画面和执行输入。在 Mac 上，所需的屏幕录制和辅助功能权限只由这个部分持有，因此终端中的程序不会获得这些权限。在 Linux 上，桌面环境通过自己的屏幕共享门户向 Kodosi 授予共享权限，并在屏幕共享期间显示自己的提示。有人观看时，电脑的菜单栏或系统托盘会显示哪些设备在观看；关闭共享或在那里点击 **停止共享**，所有观看都会结束。

在 Mac 上，Kodosi 的这个部分在为某个账号服务之前，还会用自己的提示询问 Mac 前的人：打开共享时，每个账号只询问一次。任何程序都无法让这个提示出现，只有本人在 Kodosi 中点击开关才会出现。提示会写明账号，如果服务器不是 Kodosi 的，还会写明该服务器，因此 Mac 上的程序即使用另一个账号启动自己的 Kodosi，只要那里的人不允许该账号，就什么也得不到。只有 Kodosi 的这个部分能读取或更改这些回答，它们只保存在那台 Mac 上；关闭共享或点击 **停止共享** 会收回所有回答。

当某台设备控制屏幕时，在电脑上复制的文本会发送到该设备，而在该设备上粘贴时，电脑会收到该设备的文本。被密码管理器标记为私密的文本会留在电脑上。电脑前的人使用鼠标或键盘时，观看者的输入会稍等片刻；锁定的屏幕也会保持锁定，观看者只能看到屏幕已锁定，而看不到屏幕上的内容。

## 直接连接

当你的两台设备可以在同一局域网内或通过 NAT 穿透互相直连时，终端流量会使用同样的端到端加密在设备之间直接传输，而不经过中继服务器。此时，两台设备都能看到对方的 IP 地址。如果无法直连，流量会以同样的加密通过 UDP 经由中继服务器传输，两台设备都看不到对方的 IP 地址。

为获取公网地址，Kodosi 会向 Kodosi 服务器发起查询，该服务器本来就能看到你的公网 IP。在探测或保持任一连接期间（以及此后的 1 分钟内），设备会保持单个 UDP 端口开放，并且仅接受来自正在查看你某个终端的设备的连接。与他人共享的终端始终经由中继服务器转发，因此其他用户绝不会看到你的 IP 地址。

## 服务能看到什么

后端可以看到账号和设备记录、项目成员关系、项目与终端元数据、每个终端的 Agent 类型和上报状态（例如工作中或等待批准，绝不包含终端文本）、你是否已查看该状态、路由标头、时间信息以及密文大小（走点对点直连路径的流量除外）。后端还会看到各设备的活跃状态（正在使用 Kodosi、正在使用其他桌面应用或处于空闲状态），以便通知只推送至活跃设备。后端看不到你的电脑如何被唤醒：它们的网络地址和唤醒设置只在你自己的设备之间传输，并经过端到端加密。

移动端推送通知会经由 Apple 的 APNs 或 Google 的 FCM 发送。这些推送服务商能看到处于等待、完成或失败状态的终端 ID，以及它们的 Agent 类型和状态，但绝不会看到终端名称或具体内容。

加密无法隐藏上述元数据，也不能防范服务器中断。移除设备会从那一刻起切断其访问权限；如果设备遗失或被盗，请务必同时生成新的恢复密钥，将那台设备拒之门外。当你名下仍有活跃设备时，若有人尝试在你的账号上重建全新身份，后端会将该操作延迟 24 小时执行，并通知你现有的设备以便及时取消。GitHub 和 Gitea 凭据始终保存在你的本机上。

删除账号会清除名下的所有设备、恢复数据、好友列表、现有共享以及你拥有的项目。你在他人项目中发送的消息会保留下来，但不再关联你的账号。后端会将已删除登录信息的签发者（issuer）和主体（subject）保留 30 天，以拒绝此前签发的旧令牌。

## 校验下载的文件

每个发布版本都附带 `SHA256SUMS`（包含各安装包的 SHA-256 摘要）和 `SHA256SUMS.asc`，签名所使用的 Kodosi 密钥与 apt 仓库的签名密钥一致。将这两个文件与你下载的文件放在同一目录下，然后运行：

```sh
curl -fsSLO https://updates.kodosi.com/apt/kodosi-archive-keyring.pgp
gpgv --keyring ./kodosi-archive-keyring.pgp SHA256SUMS.asc SHA256SUMS
shasum -a 256 --ignore-missing -c SHA256SUMS
```

GnuPG 提供的 `gpgv` 必须报告来自密钥 `E8007A36D199B6EE755B1EE9C612C00442E52299` 的有效签名，且 `shasum` 对你下载的文件必须输出 `OK`。

## 报告漏洞

请通过 [GitHub 私密漏洞报告](https://github.com/johnkozaris/Kodosi/security/advisories/new)提交，或发送邮件至 [security@kodosi.com](mailto:security@kodosi.com)，并附上对应的提交记录或版本号、复现步骤、影响范围以及脱敏后的日志。请勿在公开 Issue 中披露漏洞细节。
