# 보안

[English](../SECURITY.md) · [Deutsch](../de/SECURITY.md) · [Ελληνικά](../el/SECURITY.md) · [Español](../es/SECURITY.md) · [Français](../fr/SECURITY.md) · [Italiano](../it/SECURITY.md) · [日本語](../ja/SECURITY.md) · **한국어** · [简体中文](../zh-Hans/SECURITY.md)

터미널 통신과 프로젝트 내용은 내 기기에서 종단 간 암호화되며, 개인 키는 암호화되지 않은 상태로
기기를 벗어나지 않아요. 백엔드는 연결을 중계하고 암호화된 프로젝트 기록을 저장하지만, 명령을
실행하거나 그 평문을 보지는 않아요. 전체 위협 모델, 암호화 방식, 알려진 한계는
[암호화 설계](../CRYPTOGRAPHY.md)(영어)를 참고하세요. 이 설계와 구현은 아직 독립된 제3자의 보안
감사를 받지 않았어요.

## 공유로 부여되는 권한

터미널을 공유하면 공유받은 사람이 해당 컴퓨터에서 내 OS 권한 그대로 전체 제어 권한을 갖게 돼요.
터미널을 프로젝트에 공유하면 나중에 참여하는 친구를 포함해 프로젝트에 있는 내 모든 친구가 그 터미널에
접근할 수 있어요. 공유 터미널은 내 계정으로 실행되므로, 터미널에 참여한 누구나 내 권한으로
`kodosi`를 실행하고 그 컴퓨터의 파일을 읽거나 수정할 수 있어요. 그 컴퓨터를 맡길 수 있을 만큼
신뢰하는 사람과만 터미널을 공유하세요.

Kodosi는 공유 터미널이나 프로젝트 안에서 참여자나 에이전트가 수행하는 작업을 제한하지 않아요. 친구를
삭제하면 내 터미널 접근 권한이 즉시 회수되고, 서로 상대방이 소유한 프로젝트에서 나가게 돼요. 사용자를
차단해도 동일하게 적용되며, 이후 친구 요청을 보낼 수 없게 돼요.

누군가가 새로 내 터미널이나 프로젝트에 들어올 수 있게 하는 변경은, 변경이 시작된 기기의 Kodosi
앱에서 먼저 내게 물어봐요. `kodosi` 명령이 요청한 경우(예: 에이전트를 대신한 경우)도 마찬가지예요.
이는 실수와 에이전트로부터 보호하기 위한 것이며, 내가 공유한 터미널에서 입력하는 사람은 나로서
동작하므로 이 확인을 우회할 수 있어요.

승인된 내 기기는 모두 내 모든 터미널을 제어하고, 터미널을 누구와 공유할지 정하고, Kodosi가 실행 중인
내 다른 컴퓨터에서 새 터미널을 시작하며, 그 컴퓨터의 Dosi에게 메시지를 보낼 수 있어요(이때 Dosi는
내가 직접 사용할 때와 동일한 로컬 권한으로 동작해요). 기기를 제거하면 해당 기기의 터미널 및 Dosi
접근 권한이 회수돼요.

### 캔버스와 공유 브라우저

터미널에 접근할 수 있는 사람은 누구나 그 캔버스의 파일을 보고 편집하며 공유 브라우저도 사용할 수
있어요. 따라서 공유 브라우저에서는 모든 참여자가 사용해도 되는 계정으로만 로그인하세요. 공유
터미널은 비공개 터미널에 저장된 내 브라우저 로그인 정보를 절대 재사용하지 않아요. 캔버스 파일은
호스트 컴퓨터에 저장된 일반 파일이에요.

HTML 페이지와 실시간 문서 보기는 네트워크 접근, 파일 접근, 영구 저장소가 없는 격리된 프레임 안에서
실행돼요. 공유 브라우저가 활성 상태일 때는 디버그 포트와 각 창의 드라이버 포트가 `127.0.0.1` 또는
`::1`에 바인딩되므로, 같은 컴퓨터의 다른 로컬 OS 사용자 계정이 여기에 접근할 수 있어요. 공유
브라우저 안의 웹사이트는 사람이나 에이전트의 동작 한 번당 최대 한 개의 파일만 터미널 폴더에
다운로드할 수 있으며, 클립보드에는 내가 직접 복사할 때만 접근할 수 있어요.

Linux에서 Kodosi는 Chromium 샌드박스가 작동할 수 있는 환경에서만 페이지를 렌더링해요. Ubuntu에서는
앱, 렌더러 프로세스, Kodosi Browser가 Chromium 샌드박스에 필요한 사용자 네임스페이스를 생성할 수
있도록 AppArmor 프로필을 함께 제공해요. 같은 이유로 Linux에서는 공유 브라우저를 root 권한으로
실행하지 않아요.

Kodosi 앱에는 Kodosi Browser가 기본 포함되어 있지 않아요. 컴퓨터에서 공유 브라우저를 처음 열 때
Kodosi가 GitHub의 Kodosi 릴리스에서 이를 다운로드하고, 이후 `updates.kodosi.com`에 있는 Kodosi
업데이트 피드에서 매일 업데이트를 확인해요. 업데이트 피드에 Kodosi 업데이트 키의 유효한 서명이 있고
파일의 SHA-256 해시가 피드와 일치할 때만 다운로드를 허용해요.

### Kodosi Browser가 Google에 보내는 정보

Kodosi Browser는 Chromium이며, 다음 Google 서비스에 스스로 연결해요. 어느 연결에서도 내 쿠키는
보내지 않아요.

- 구성 요소 업데이트(예: 해지된 인증서 목록): 약 5시간마다 `update.googleapis.com`에 새 버전이
  있는지 묻고, Google 다운로드 서버(예: `edgedl.me.gvt1.com`)에서 다운로드해요. 각 구성 요소의 ID와
  버전, 브라우저 자체 버전, 운영 체제와 프로세서를 보내지만 브라우징 데이터는 보내지 않아요.
- 세이프 브라우징: `safebrowsing.googleapis.com`에서 위험한 사이트 목록을 받아 보관하며, 이때 목록의
  상태만 보내요. 페이지 주소가 목록과 일치하면 주소 해시의 앞 4바이트를 보내고, 주소 자체는 절대
  보내지 않아요. 내 컴퓨터에서 실행되는 피싱 검사가 어떤 페이지를 피싱으로 판단하면, 확인을 위해 그
  페이지의 주소를 `sb-ssl.google.com`에 보내요.
- 네트워크 시간: 시간이 확실하지 않을 때 `clients2.google.com`에 물어봐요. 그 응답으로 내 컴퓨터의
  시계가 틀려도 사이트 인증서가 만료되었는지 알 수 있어요. 이 요청에는 나에 관한 정보가 전혀 담기지
  않아요.

**Google 양식 예측**은 **설정 › 브라우저**에서 켜기 전까지 꺼져 있어요. 켜면 Kodosi Browser가
표시하는 각 양식에 대해 사이트 이름과 양식의 입력란 이름으로 만든 해시를
`content-autofill.googleapis.com`에 보내고, Google은 각 입력란의 용도를 알려 줘요. 양식을 제출하면
각 입력란에 어떤 종류의 데이터가 들어 있었는지도 알리지만, 내가 입력한 내용은 절대 보내지 않아요.
Kodosi Browser는 검색하기 전에 `www.google.com`에 미리 연결하는 일이 절대 없으며, Chrome 자체
주소창에서 AI 모드를 제공해도 되는지 내 Google 쿠키를 사용해 Google에 묻지도 않아요.

**교차 사이트 쿠키**도 **설정 › 브라우저**에서 켜기 전까지 꺼져 있어요. 꺼져 있는 동안에는 YouTube
동영상이나 로그인 버튼처럼 다른 사이트의 페이지 안에 표시되는 사이트가 그곳에서 자신의 쿠키를 받지
못하므로, 내가 방문하는 여러 사이트에 걸쳐 나를 알아볼 수 없어요.

## 직접 연결

내 기기 두 대가 같은 로컬 네트워크에 있거나 NAT 통과를 통해 서로 직접 연결될 수 있으면, 터미널
통신은 중계 서버를 거치지 않고 동일한 종단 간 암호화가 적용된 상태로 두 기기 사이를 바로 오가요.
이때 양쪽 기기는 서로의 IP 주소를 확인하게 돼요.

기기의 공인 IP 주소를 확인하기 위해 Kodosi는 Cloudflare STUN 서버에 질의하며, 이때 해당 서버가
기기의 IP 주소를 보게 돼요. 직접 연결을 탐색하거나 유지하는 동안(그리고 그 후 1분 동안) 기기는
UDP 포트 하나를 열어 두고 승인된 내 기기에서 오는 연결만 수락해요. 다른 사람과 공유한 터미널은 항상
중계 서버를 거치므로, 다른 사용자에게 내 IP 주소가 노출되지 않아요.

## 서비스가 보는 정보

백엔드는 계정 및 기기 기록, 프로젝트 멤버십, 프로젝트와 터미널의 메타데이터, 각 터미널의 에이전트
종류와 보고된 상태(작업 중, 승인 대기 등이며 터미널 텍스트는 절대 보지 않아요), 해당 상태를 이미
확인했는지 여부, 라우팅 헤더, 통신 시각, 암호문 크기를 볼 수 있어요(P2P 직접 연결로 오가는 트래픽은
제외). 또한 알림이 현재 사용 중인 기기로만 전달되도록 기기별 활동 상태(Kodosi 사용 중, 다른
데스크톱 앱 사용 중, 유휴 상태)도 확인해요. 컴퓨터를 깨우는 방법은 볼 수 없어요. 컴퓨터의 네트워크
주소와 깨우기 설정은 종단 간 암호화된 채 내 기기들 사이에서만 오가요.

모바일 푸시 알림은 Apple의 APNs 또는 Google의 FCM을 거쳐 전달돼요. 이 서비스들은 대기 중, 완료됨,
실패한 터미널의 ID와 에이전트 종류 및 상태만 볼 뿐, 터미널 이름이나 내용은 보지 못해요.

암호화는 이러한 메타데이터를 숨기지 못하며, 서버 장애도 막아 주지 않아요. 기기를 제거하면 그
시점부터 접근이 차단되며, 기기를 분실하거나 도난당한 경우에는 그 기기를 막기 위해 새 복구 키도 함께
생성하세요. 활성 기기가 남아 있는 상태에서 누군가 내 계정에 새 신원을 시작하려 하면, 백엔드가 이를
24시간 지연시키고 기존 기기에 알림을 보내 취소할 수 있게 해 줘요. GitHub와 Gitea 자격 증명은 내
컴퓨터에만 남아요.

계정을 삭제하면 등록된 기기, 복구 데이터, 친구 목록, 활성 공유, 소유한 프로젝트가 모두 삭제돼요.
다른 사람의 프로젝트에 남긴 메시지는 연결된 계정 정보 없이 남아요. 백엔드는 이전에 발급된 토큰을
거부하기 위해 삭제된 로그인 계정의 발급자(issuer)와 주체(subject) 정보를 30일 동안 보관해요.

## 다운로드 검증하기

모든 릴리스에는 각 배포 파일의 SHA-256 해시가 담긴 `SHA256SUMS` 파일과, apt 저장소 서명에도
사용되는 동일한 Kodosi 키로 서명된 `SHA256SUMS.asc` 파일이 포함되어 있어요. 두 파일을 다운로드한
파일과 같은 폴더에 두고 다음 명령을 실행하세요.

```sh
curl -fsSLO https://updates.kodosi.com/apt/kodosi-archive-keyring.pgp
gpgv --keyring ./kodosi-archive-keyring.pgp SHA256SUMS.asc SHA256SUMS
shasum -a 256 --ignore-missing -c SHA256SUMS
```

GnuPG의 `gpgv`가 키 `E8007A36D199B6EE755B1EE9C612C00442E52299`의 유효한 서명(good signature)을
보고해야 하며, `shasum` 출력에서 해당 파일에 `OK`가 표시되어야 해요.
