# セキュリティ

[English](../SECURITY.md) · [Deutsch](../de/SECURITY.md) · [Ελληνικά](../el/SECURITY.md) · [Español](../es/SECURITY.md) · [Français](../fr/SECURITY.md) · [Italiano](../it/SECURITY.md) · **日本語** · [한국어](../ko/SECURITY.md) · [简体中文](../zh-Hans/SECURITY.md)

あなたのデバイスは、ターミナルの通信とルームの内容をエンドツーエンドで暗号化します。秘密鍵はデバイスから出ません。バックエンドは接続を中継し、暗号化されたルームのデータを保存しますが、コマンドを実行することも、その平文を見ることもありません。[暗号化の設計](../CRYPTOGRAPHY.md)（英語）には、脅威モデル、仕組み、既知の制限を記載しています。まだ独立した第三者による監査は受けていません。

## 共有で渡されるもの

ターミナルを共有すると、ホストのユーザーの OS 権限でのフル操作を渡すことになります。ルームにいる人は全員、後から招待されたメンバーも含めて、ルームの共有ターミナルを使えます。1 つのターミナルを共有しても、それ以外のものは共有されません。Kodosi は、ターミナルやルームを共有するすべての人と、そのターミナル内のプログラムやエージェントを信頼し、その操作を制限しません。承認済みのデバイスはどれも、あなたのすべてのターミナルを操作でき、Kodosi が動いているほかのコンピュータで新しいターミナルを起動できます。どのデバイスからでも、あなたのコンピュータの Dosi に書き込むことができ、Dosi はそのコンピュータで直接書き込んだときと同じようにそこで動きます。削除したデバイスは、もう Dosi に書き込めません。

ターミナルを開ける人は全員、そのキャンバスのファイルも見え、共有ブラウザも使えます。そのため、そこでは全員が操作してよい場所にだけサインインしてください。共有ターミナルが、あなたの保存済みのサインイン情報を持つことはありません。キャンバスのファイルは普通のファイルで、ターミナルを開ける人は全員編集できます。キャンバスのページとライブドキュメントは、ネットワークもファイルも永続的なストレージもない閉じたフレームで動きます。共有ブラウザが起きている間、そのデバッグポートと各ウィンドウのドライバポートは `127.0.0.1` で待ち受けており、同じコンピュータのほかのアカウントからアクセスできます。共有ブラウザ内のサイトは、人またはエージェントの操作 1 回につき 1 つのダウンロードをターミナルのフォルダに保存し、クリップボードにはあなたがコピーしたときだけアクセスします。あるデバイスが別のコンピュータのターミナルのブラウザを開くと、そのコンピュータは数秒間 TCP ポートで待ち受け、両者が直接つながれるようにします。通過できるのはそのデバイスだけで、ターミナルの暗号化が使われます。Linux アプリは、Chromium がサンドボックス化できる場合にだけページを表示します。Ubuntu では、アプリの AppArmor プロファイルにより、アプリ、そのページのプロセス、Kodosi Browser がサンドボックスに必要なユーザー名前空間を作成できます。同じ理由で、Linux では共有ブラウザを root として実行しません。アプリには Kodosi Browser は含まれていません。コンピュータが初めて共有ブラウザを開くと、そのホストが `updates.kodosi.com` のフィードからブラウザを取得し、毎日そこで新しいバージョンを確認します。ホストがダウンロードを使うのは、フィードに Kodosi のアップデート用の鍵の署名があり、ダウンロードの SHA-256 がフィードの示す値と一致する場合だけです。

## サービスから見えるもの

サービスから見えるのは、アカウントとデバイスの記録、ルームのメンバー、ルームとターミナルのメタデータ、各ターミナルのエージェントと状態（作業中や承認待ちなど。テキストは見えません）、ルーティング情報、タイミング、暗号文のサイズです。暗号化はこれらのメタデータを隠さず、障害も防ぎません。削除したデバイスは、その時点からアクセスできなくなります。紛失または盗難にあったデバイスを削除したら、そのデバイスを締め出すために新しいリカバリーキーを作成してください。GitHub と Gitea の認証情報はあなたのコンピュータに残ります。

アカウントを削除すると、そのデバイス、リカバリーデータ、フレンド、共有、所有するルームが削除されます。ほかの人のルームのメッセージは、アカウントのない状態で残ります。サービスは古いトークンを拒否するため、削除したサインインの発行者とサブジェクトを 30 日間保持します。

## ダウンロードを確認する

各リリースには、すべてのファイルの SHA-256 を記載した `SHA256SUMS` と、そのリストの署名 `SHA256SUMS.asc` があります。署名に使う Kodosi の鍵は、apt リポジトリの署名にも使われています。この 2 つのファイルをダウンロードしたファイルと同じ場所に置いて、次を実行してください。

```sh
curl -fsSLO https://updates.kodosi.com/apt/kodosi-archive-keyring.pgp
gpgv --keyring ./kodosi-archive-keyring.pgp SHA256SUMS.asc SHA256SUMS
shasum -a 256 --ignore-missing -c SHA256SUMS
```

GnuPG の `gpgv` が鍵 `E8007A36D199B6EE755B1EE9C612C00442E52299` による正しい署名と表示し、`shasum` がダウンロードしたファイルに OK と表示することを確認してください。

## 脆弱性を報告する

[非公開の脆弱性報告](https://github.com/johnkozaris/Kodosi/security/advisories/new)を使うか、[security@kodosi.com](mailto:security@kodosi.com) に、リビジョン、手順、影響、機密情報を伏せたログを添えてご連絡ください。詳細は公開の Issue に書かないでください。
