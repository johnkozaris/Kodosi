# セキュリティ

[English](../SECURITY.md) · [Deutsch](../de/SECURITY.md) · [Ελληνικά](../el/SECURITY.md) · [Español](../es/SECURITY.md) · [Français](../fr/SECURITY.md) · [Italiano](../it/SECURITY.md) · **日本語** · [한국어](../ko/SECURITY.md) · [简体中文](../zh-Hans/SECURITY.md)

ターミナルの通信とプロジェクトの内容はお使いのデバイス上でエンドツーエンド暗号化され、秘密鍵が暗号化されないままデバイス外に出ることはありません。バックエンドは接続のルーティングと暗号化されたプロジェクト記録の保存を行いますが、コマンドを実行することも、それらの平文を見ることもありません。詳細な脅威モデル、暗号方式、既知の制限については[暗号化の設計](../CRYPTOGRAPHY.md)（英語）をご覧ください。なお、本設計および実装は独立した第三者機関による監査をまだ受けていません。

## 共有で与えられる権限

ターミナルを共有すると、相手にはそのコンピュータ上でのあなたの OS 権限と同等のフル操作権限が与えられます。プロジェクトに共有したターミナルには、後から参加する人を含め、そのプロジェクトに参加しているあなたのフレンド全員がアクセスできます。共有ターミナルはあなたとして実行されるため、参加者はあなたとして `kodosi` を実行したり、そのコンピュータ上のファイルを読み書きしたりできます。そのコンピュータを任せられる相手にだけターミナルを共有してください。

Kodosi は、共有ターミナルやプロジェクトの中で参加者やそのエージェントが行う操作を制限しません。フレンドを削除すると、あなたのターミナルへのアクセス権は直ちに失われ、お互いが相手の所有するプロジェクトから退出します。ユーザーをブロックした場合も同様で、さらにその相手からの今後のフレンドリクエストも防ぎます。

あなたのターミナルやプロジェクトに新しく誰かが入れるようになる変更は、その変更が始まったデバイスの Kodosi アプリで必ず事前に確認されます。`kodosi` コマンドが求めた場合（たとえばエージェントのため）も同じです。これは誤操作やエージェントから守るためのもので、あなたが共有したターミナルで入力している人はあなたとして動作するため、この確認を回避できます。

承認済みの各デバイスからは、自分のすべてのターミナルの操作と共有相手の選択、Kodosi を起動している自分のほかのコンピュータ上での新規ターミナル起動、さらにそれらのコンピュータ上の Dosi へのメッセージ送信が可能です（Dosi は、あなたが直接操作したときと同じローカル権限で動作します）。デバイスを削除すると、ターミナルと Dosi へのアクセス権が取り消されます。

### キャンバスと共有ブラウザ

ターミナルにアクセスできる人は全員、キャンバス上のファイルを閲覧・編集でき、共有ブラウザも利用できます。そのため、共有ブラウザでは参加者全員が使って問題ないアカウントにだけサインインしてください。共有ターミナルが、プライベートなターミナルの保存済みブラウザログイン情報を再利用することはありません。キャンバス上のファイルはホストコンピュータ上の通常のファイルです。

HTML ページとライブドキュメントのビューは、ネットワークアクセス、ファイルアクセス、永続ストレージを持たない隔離されたフレーム内で動作します。共有ブラウザが起動している間、そのデバッグポートと各ウインドウのドライバポートは `127.0.0.1` または `::1` にバインドされるため、同じコンピュータ上の別 OS ユーザーアカウントからは到達できます。共有ブラウザ内のサイトがターミナルのフォルダへ保存できるダウンロードは、人またはエージェントの操作 1 回につき最大 1 件までで、クリップボードへのアクセスは明示的にコピーしたときに限られます。

Linux では、Chromium のサンドボックスが動作する環境でのみページをレンダリングします。Ubuntu では、アプリ本体、レンダラープロセス、Kodosi Browser が Chromium サンドボックスに必要なユーザー名前空間を作成できるよう、専用の AppArmor プロファイルを同梱しています。同じ理由から、Linux で共有ブラウザを root として実行することはありません。

Kodosi のアプリには Kodosi Browser が同梱されていません。コンピュータで初めて共有ブラウザを開くときに、Kodosi が GitHub 上の Kodosi のリリースからダウンロードし、その後は `updates.kodosi.com` にある Kodosi のアップデートフィードで毎日アップデートを確認します。ダウンロードが受け入れられるのは、アップデートフィードに Kodosi のアップデート鍵による有効な署名があり、かつファイルの SHA-256 がフィードの値と一致する場合だけです。

### Kodosi Browser が Google に送信する情報

Kodosi Browser は Chromium であり、次の Google のサービスに自ら接続します。いずれの接続でも、あなたの Cookie は送信されません。

- コンポーネント（失効した証明書のリストなど）のアップデート: 約 5 時間ごとに `update.googleapis.com` に新しいバージョンを問い合わせ、Google のダウンロードサーバー（`edgedl.me.gvt1.com` など）からダウンロードします。送信するのは各コンポーネントの ID とバージョン、ブラウザ自体のバージョン、OS とプロセッサの情報で、閲覧データは送信しません。
- セーフ ブラウジング: `safebrowsing.googleapis.com` から危険なサイトのリストを取得して保持しており、その際に送信するのはリストの状態だけです。ページのアドレスがリストに一致した場合は、アドレスのハッシュの先頭 4 バイトを送信し、アドレスそのものは決して送信しません。お使いのコンピュータ上で行うフィッシング検出がページをフィッシングと判断した場合は、確認のためにそのページのアドレスを `sb-ssl.google.com` に送信します。
- ネットワーク時刻: 時刻が確かでないときは `clients2.google.com` に問い合わせます。その応答により、お使いのコンピュータの時計がずれていても、サイトの証明書の有効期限が切れているかどうかがわかります。このリクエストには、あなたに関する情報は何も含まれません。

**Google によるフォーム予測** は、**設定 › ブラウザ** でオンにするまでオフのままです。オンにすると、Kodosi Browser は表示する各フォームについて、サイト名とフォームの各欄の名前から作ったハッシュを `content-autofill.googleapis.com` に送信し、Google は各欄の用途を回答します。フォームを送信したときは、各欄にどの種類のデータが入っていたかも伝えますが、入力した内容は決して伝えません。Kodosi Browser が検索に先立って `www.google.com` に接続することはなく、Chrome 自体のアドレスバーで AI モードを提供してよいかどうかを、あなたの Google の Cookie を付けて Google に問い合わせることもありません。

**クロスサイト Cookie** も、**設定 › ブラウザ** でオンにするまでオフのままです。オフの間は、YouTube の動画やサインインボタンのように別のサイトのページ内に表示されるサイトは、そこで自身の Cookie を受け取れないため、あなたが訪れるサイトをまたいであなたを識別することはできません。

### コンピュータの画面

コンピュータの Kodosi の設定で画面共有をオンにすると、承認済みのどのデバイスからも、そのコンピュータのターミナルのキャンバスで、ターミナルだけでなくコンピュータの画面全体を表示・操作できるようになります。フレンドには、共有しているターミナルでも画面は決して見えません。映像、入力、クリップボードのテキストは、ターミナルと同じようにエンドツーエンドで暗号化されて送られます。画面の取り込みと入力は、Kodosi の独立した部分が行います。Mac では、そのために必要な画面収録とアクセシビリティのアクセス権をこの部分だけが持つため、ターミナルのプログラムには与えられません。Linux では、デスクトップが画面共有ポータルを通じて Kodosi に共有を許可し、画面を共有している間は独自の通知を表示します。X11 のデスクトップにはこのポータルがなく、セッションのどのプログラムも画面を表示・操作できるため、Kodosi で共有をオンにするだけで使えます。誰かが見ている間はコンピュータのメニューバーまたはシステムトレイに見ているデバイスが表示され、共有をオフにするか、そこで **共有を停止** を押すと、すべての表示が終わります。

Mac では、Kodosi のこの部分は、アカウントに応じる前に、Mac の前にいる人に独自の通知でもう一度確認します。確認は共有をオンにしたときに、アカウントごとに一度だけ行われます。どのプログラムもこの通知を表示させることはできず、表示されるのは本人が Kodosi のスイッチをクリックしたときだけです。通知にはアカウントと、Kodosi のサーバでない場合はそのサーバが表示されるため、Mac 上のプログラムが別のアカウントで独自の Kodosi を起動しても、そこにいる人がそのアカウントを許可しない限り何も得られません。回答を読んだり変えたりできるのは Kodosi のこの部分だけで、回答はその Mac にだけ残ります。共有をオフにするか **共有を停止** を押すと、すべての回答が取り消されます。

デバイスが画面を操作している間、コンピュータでコピーしたテキストはそのデバイスに送られ、そのデバイスで貼り付けると、そのデバイスのテキストがコンピュータに渡ります。パスワードマネージャーが非公開として指定したテキストは、コンピュータから出ません。コンピュータの前にいる人がマウスやキーボードを使っている間は、見ている側の入力は少し待たされます。また、ロックされた画面はロックされたままで、見ている側には画面がロックされていることだけが見え、画面の内容は見えません。

## 直接接続

自分のデバイス 2 台が同一 LAN 内や NAT トラバーサル経由で直接到達できる場合、ターミナル通信は中継サーバーを通らず、同じエンドツーエンド暗号化のままデバイス間で直接やり取りされます。このとき、双方のデバイスには互いの IP アドレスが見えます。直接到達できない場合は、同じ暗号化のまま UDP で中継サーバーを経由し、どちらのデバイスにも相手の IP アドレスは見えません。

パブリックアドレスを取得するため、Kodosi は Kodosi サーバーへ問い合わせます（このサーバーにはもともとその IP アドレスが見えています）。いずれかの接続の探索中・維持中およびその後の 1 分間、デバイスは UDP ポートを 1 つだけ開いた状態にし、自分のターミナルを表示しているデバイスからの接続のみを受け付けます。ほかのユーザーと共有しているターミナルは常に中継サーバーを経由するため、ほかのユーザーにあなたの IP アドレスが見えることはありません。

## サービスから見える情報

バックエンドには、アカウントとデバイスの記録、プロジェクトのメンバー構成、プロジェクトとターミナルのメタデータ、各ターミナルのエージェント種別と報告された状態（作業中や承認待ちなど。ターミナルのテキストは見えません）、その状態を確認済みかどうか、ルーティングヘッダー、通信のタイミング、暗号文のサイズが見えます（デバイス間の直接ピアツーピア通信を除く）。また、アクティブなデバイスにだけ通知を届けるため、各デバイスのアクティビティ状態（Kodosi を使用中、別のデスクトップアプリを使用中、またはアイドル）も見えます。コンピュータをスリープから復帰させる方法は見えません。ネットワークアドレスやスリープ解除の設定は、エンドツーエンド暗号化されたまま、あなた自身のデバイス間でのみやり取りされます。

モバイルへのプッシュ通知は Apple の APNs または Google の FCM を経由します。これらのプロバイダには、待機中・完了・失敗したターミナルの ID、エージェント種別、状態が見えますが、ターミナル名や内容は見えません。

暗号化によってこれらのメタデータが隠されることはなく、サーバー障害も防げません。デバイスを削除すると、その時点からアクセスが遮断されます。デバイスを紛失または盗難された場合は、そのデバイスを締め出すために新しいリカバリーキーも生成してください。アクティブなデバイスが残っているアカウントで誰かが新しいアイデンティティを開始しようとした場合、バックエンドはそれを 24 時間保留し、その間に既存のデバイスへ通知するため、キャンセルできます。GitHub と Gitea の認証情報はあなたのコンピュータに残ります。

アカウントを削除すると、そのデバイス、リカバリーデータ、フレンド一覧、有効な共有、所有するプロジェクトが削除されます。ほかの人のプロジェクトに投稿したメッセージは、アカウントとの関連付けがない状態で残ります。発行済みトークンを拒否するため、バックエンドは削除されたサインインの発行者とサブジェクトを 30 日間保持します。

## ダウンロードを検証する

各リリースには、全成果物の SHA-256 ダイジェストをまとめた `SHA256SUMS` と、apt リポジトリと同じ Kodosi 鍵で署名された `SHA256SUMS.asc` が含まれています。両方のファイルをダウンロードしたファイルと同じディレクトリに置き、次を実行してください。

```sh
curl -fsSLO https://updates.kodosi.com/apt/kodosi-archive-keyring.pgp
gpgv --keyring ./kodosi-archive-keyring.pgp SHA256SUMS.asc SHA256SUMS
shasum -a 256 --ignore-missing -c SHA256SUMS
```

GnuPG の `gpgv` が鍵 `E8007A36D199B6EE755B1EE9C612C00442E52299` による正しい署名であることを報告し、`shasum` が対象ファイルに対して `OK` と出力することを確認してください。

## 脆弱性を報告する

[GitHub の非公開の脆弱性報告](https://github.com/johnkozaris/Kodosi/security/advisories/new)を利用するか、コミットまたはバージョン、再現手順、影響、機密情報を伏せたログを添えて [security@kodosi.com](mailto:security@kodosi.com) までメールでご連絡ください。脆弱性の詳細は公開の Issue に記載しないでください。
